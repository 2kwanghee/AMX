# 보류 — 상용 SaaS 준비 (2026-08-09 사용자 결정)

> **내재화(사내 운영) 안정화 기간이 끝난 뒤 사용자 결정으로 재개한다.** 그 전에는 착수하지 않는다.
> 구조·배관은 이미 SaaS-ready로 병합돼 있으므로(F1~F5), 여기 항목들은 "상용 전환 시 마지막 마일"이다.

## 보류 항목

| 항목 | 내용 | 재개 시 선행 조건 |
|---|---|---|
| **F2 실 KMS 어댑터** (G19·G20) | `AMX_KEK_PROVIDER=aws-kms\|vault` 어댑터 구현. 현재 local(단일 env 시크릿) — 격리·구조는 완비, 기밀 강화는 실 KMS부터 | KMS 벤더 결정. **local→KMS 혼재 시 기존 DEK 재래핑(`rewrap_secrets.py`) 선행 필수** |
| **A2 ClickEye 연동** (O8) | AMS 조회 API를 읽는 방식·범위. 권장: read-only 엔드포인트 + 전용 API 키(관리자 토큰 분리) | ClickEye 쪽 요구 확정 |
| **A3 API-key 계정 정책** (O3) | 구독 쿼터 없어 95% 임계 무의미 — 스위칭 풀 포함 여부 정책 | 상용 계정 구성 확정 시 |
| **G14 로그인 타이밍 오라클** | 미존재 email의 bcrypt 스킵으로 존재 여부 타이밍 노출. dummy bcrypt 균일화 | 외부 노출 시점(상용) 전 |
| **G16 mask_secret 상관 핸들** | 4hex 교차 테넌트 상관 가능성 — 수용 명시됨, 상용 전 재평가 | 상용 전 재평가 |
| **F5 과금 대상·요금제 확정** | outbox·스키마는 완료. 실제 청구 주체·단가·인보이스 생성은 미정 | 상용 과금 모델 결정 (G26 정정 수단은 ②에서 선행) |

## 보류가 아닌 것 (혼동 주의)

- **F1 RBAC · F2 봉투암호화(local) · F3 멀티인스턴스 · F4 정책 중앙화 · F5 과금 outbox** — 이미 완료.
  내재화 운영에서도 그대로 사용한다.
- **B1·B4(①)** — 배포 보안은 내재화에도 필수라 보류 대상이 아니다.
- **G25·G26(②)** — 내부 청구 데이터의 정합성 문제라 내재화 중에도 진행한다.
