Context · 왜 만들었나

계정 관리를 수작업으로 하면, 규모가 커질수록 반드시 새는 곳이 생긴다

Claude 유료 계정이 여러 개, 작업 서버가 여러 대. 계정마다 사용 한도가 있어 한쪽만 쓰면 금세 막힌다. 그래서 누군가 서버에 접속해 계정을 나눠주고, 한도가 차면 갈아끼우고, 다 쓰면 회수해야 한다.

이 반복을 사람이 하면 실수·지연·중단이 쌓인다. AMX는 이 전 과정을 중앙 서버 하나와 서버별 상주 프로그램으로 자동화한다.

Service ① · 배정·회수

배정은 재전달, 회수는 완전 분리. 실패해도 스스로 낫는다

  • 배정·하달은 콘솔에서 계정을 서버에 지정하는 데서 출발한다. 자격증명을 암호화해 에이전트로 보내면 tsamx에 등록된다.
  • 회수는 늘 purge다. provider와 무관하게 purge_local_copy=true로 해당 서버에서 완전히 떼어내고 이력은 detached 배정 행과 이벤트로만 남긴다.
  • credential 역동기화. 서버에서 회전된 자격증명을 중앙이 자동으로 최신화한다. 그래야 다른 서버로 옮길 때 죽은 정보를 넘기지 않는다.

Service ② · 자동 전환

사용률 95%에서 다음 계정으로 넘어가 작업을 멈추지 않는다

자동 스위칭 임계값. tsamx autoswitch.threshold에 닿으면 후보를 랭킹해 교체한다.
  • 중앙 정책 하달. SetPolicy로 threshold·strategy·cooldown·hysteresis 네 축을 세션마다 다시 못 박는다.

  • 전 계정 소진 감지 시 크리티컬 이벤트로 즉시 통지한다.

Service ③ · 실시간 관제

상황판·경보 13종·웹훅으로 이상을 조기에 밖으로 밀어낸다

  • 상황판. 콘솔이 5~10초마다 폴링해 서버·계정·배정 상태를 비춘다. 30초 하트비트가 끊기면(last_seen_at 만료) 서버는 offline으로 넘어간다.
  • 자가복원 경보. 이벤트가 유실돼도 reconcile-on-report 재조회로 경보를 다시 세운다.
  • 아웃박스 웹훅. 경보 전이를 같은 트랜잭션에 스테이징하고 HMAC-SHA256 서명으로 무결성을 지켜 밖으로 내보낸다(at-least-once).

경보 kind는 13종. 서버·계정·테넌트·시스템 범위로 나뉜다.

Service ④ · 사용량·비용

토큰을 종류별로 실측해 과금 근거를 추정이 아닌 원장으로 남긴다

  • Langfuse usageByType. 러너 세션 훅이 보낸 기록을 중앙이 폴링해서 토큰을 종류별로 각 컬럼에 실측값으로 쌓는다.
  • 내부 청구 집계. usage 원장을 닫힌 UTC 일 단위 billing_events로 롤업한다(멱등 앵커로 중복 방지). 외부 결제는 아직 붙이지 않았다.
  • 영구 보존. usage_daily_rollup은 삭제 정책을 타지 않는다. 비용 배분의 입력이라 영구히 남긴다(원문 스냅샷은 90일).
