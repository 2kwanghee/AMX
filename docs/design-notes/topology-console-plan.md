# 상황판 콘솔화 계획 (2026-08-22)

상황판(토폴로지)을 이동 전용 화면이 아니라 그 안에서 운영 작업이 끝나는 콘솔로
바꾼다. 병행 조사(프론트 구조 1건, 동기화 루프 1건)로 확정한 사실 위에서 다섯
단계로 나눠 순차 진행한다.

## 조사로 확정된 사실

1. **트래픽선 클릭 팝오버는 코드에 지금도 있다.** `TopologyView.tsx:608-612`가
   히트 패스 클릭을 받고 `:796-861`이 비활성화·회수·즉시전환 팝오버를 그린다.
   동작하지 않는 이유는 자유 배치 캔버스의 회귀다 — 선 SVG는
   `z-index:0`(globals.css:672)인데 `.topo-canvas-area`가 `z-index:1`로 전면을
   덮어(globals.css:948) 포인터가 히트 패스에 닿지 못한다. 3열 그리드 폴백에서만
   열 사이 빈 공간으로 클릭이 통했다.
2. **"동기화중" 무한루프의 원인은 `queued` 명령에 타임아웃이 없어서다.** UI는
   할당의 `pendingCommandId`만 보고 동기화중을 표시하는데(`AssignmentsPanel.tsx:18-25`,
   `TopologyView.tsx:393`), 이 값은 명령이 `queued`로 삽입될 때 세팅되고
   에이전트 ack가 와야 해제된다(`commands.py:126`, `reconcile.py:153,233`).
   타임아웃 스위퍼는 `sent`만 회수하므로(`commands.py:506-512`) 에이전트
   미설치·구버전(세션 자체가 `FAILED_PRECONDITION`으로 abort,
   `grpc/server.py:339-344`)이면 명령이 영구 `queued`로 남는다. `delivering`
   상태에는 UI 탈출 액션도 없다(`client.ts:373-377`). 부경로로, 풀 체인은
   REJECTED ack 후 `pending` 분기에서 만료 검사 없이 즉시 재발행해
   (`pool.py:1563-1565`) 수명 상한이 꺼져 있으면 무한 재발행이 된다.
3. **`assigned`("연결됨") 배지는 색상 규칙이 없다.** globals.css:136-150의
   초록·호박·빨강 그룹 어디에도 없어 기본 회색(globals.css:129-134)으로
   떨어진다. 미연결처럼 보이는 게 당연했다.
4. **노드 좌표는 이미 드래그·저장 인프라가 있다.** localStorage
   `amx.topo.layout.<tenantId>`(version 1)에 서버·계정 좌표를 저장하고
   (`TopologyView.tsx:69-102`), 풀 레인만 상수 좌표(`POOL_X=744`, `LANE_TOP=8`,
   `LANE_W=216`)로 고정돼 있다(`TopologyView.tsx:53-59,640-644`).
5. **메뉴 이동 클릭 지점**: 스탯 타일 4종(`StatBar.tsx:59`), 서버 노드
   (`TopologyView.tsx:664,708`), 계정 노드(`:687,729`). 소비처는
   `dashboard/page.tsx:162`.

## 단계별 계획

### 1단계 — 동기화 무한루프 해소 (백엔드 중심, R2)

- `commands.py` `sweep_sent_timeouts`에 `queued` 노후 회수를 추가한다. 기준은
  `created_at`이 임계(기본 90초 × 여유 계수)를 넘긴 행이며, 기존
  `_revert_assignment_on_send_failure`(`commands.py:581-633`)를 재사용해
  `pending_command_id` 해제·`last_error` 기록까지 한 번에 처리한다.
- `request_deliver`(`commands.py:106-131`)에 서버 온라인 가드를 넣는다. 서버가
  한 번도 접속한 적 없거나(`last_seen_at IS NULL`) offline이면 409로 즉시
  거부해 애초에 영구 queued를 만들지 않는다. 풀 자동화 경로가 같은 함수를
  타는지 확인하고, 자동화 쪽은 예외 대신 실패 기록으로 처리한다.
- `pool.py:1563` `pending` 분기에 `delivering` 분기와 같은 만료 검사
  (`pool.py:1572-1575` 패턴)를 추가해 REJECTED 즉시 재발행 루프를 끊는다.
- 프론트는 `client.ts:373-377`에서 `delivering` 상태에 회수(recall)를 허용한다.
  서버 측 `request_recall`은 이미 `delivering`을 받는다(`commands.py:170`).
  타임아웃이 서버에서 `lastError`로 남으면 기존 `SyncCell` 실패 표시가 그대로
  동작하므로 프론트 별도 stale 판정은 만들지 않는다.
- 완료조건: ams-server pytest 통과 + 신규 테스트(미접속 서버 deliver 409, queued
  타임아웃 회수, 풀 pending 만료) 통과.

### 2단계 — "연결됨" 배지 스타일 (R0)

`.badge.assigned`를 틸 액센트(`--accent`/`--accent-soft`) 그룹으로 추가한다.
초록(사용 가능)과 구분되는 "연결되어 사용 중" 색이다. CSS 두 줄.

### 3단계 — 트래픽선 클릭 복원 (R1)

`.topo-canvas-area`에 `pointer-events: none`을 주고 직계 자식(노드·레인·밴드
라벨)만 `pointer-events: auto`로 되살린다. 빈 영역 클릭이 아래 SVG 히트
패스로 떨어져 팝오버가 다시 열린다. 캔버스 가로 스크롤(`topo-has-lanes`)과
노드 드래그가 깨지지 않는지 함께 확인한다.

### 4단계 — 메뉴 이동 제거, 상황판 내 완결 (R2)

- 4a. ServersPanel·AccountsPanel 안의 모달(사용량·이벤트·정책·등록 토큰·에이전트
  업데이트·계정 수정·서버 등록·계정 등록 위저드)을 공용 컴포넌트로 추출한다.
  동작 불변의 순수 이동이다.
- 4b. 서버·계정 노드 클릭을 메뉴 이동 대신 액션 팝오버로 바꾼다. 서버 팝오버:
  전환 모드 토글·사용량 갱신·사용량·이벤트·정책·등록 토큰·에이전트 업데이트·
  삭제. 계정 팝오버: 수정·삭제. 상황판 툴바에 서버 등록·계정 등록 버튼을
  추가하고, 스탯 타일의 탭 이동(`onGo`)을 제거한다. 기존 메뉴 패널 자체는
  남긴다 — 제거하는 것은 상황판에서 밖으로 나가는 클릭뿐이다.
- 완료조건: 상황판 요소 클릭으로 탭이 바뀌는 경로 0건, 위 액션 전부가 상황판
  안에서 실행·완료.

### 5단계 — 풀 레인 이동·리사이즈와 디자인 (R1)

- 레인(충전중·배급처) 각각을 노드와 같은 드래그 인프라로 이동 가능하게 하고,
  우하단 그립으로 폭·높이 리사이즈를 지원한다. 좌표·크기는 기존 localStorage
  레이아웃에 `lane:cooling`/`lane:ready` 키로 저장하고 스키마 version을 2로
  올린다(v1 데이터는 노드 좌표만 이관).
- 디자인은 점선 사각형에서 벗어나 헤더 아이콘·수량 배지·옅은 배경 틴트·상단
  액센트 보더를 준다. 기존 캔버스 토큰(`--canvas-*`)만 사용한다.
- 완료조건: 레인 드래그·리사이즈 후 새로고침에도 위치 유지, 축소 화면(그리드
  폴백)에서 기존 동작 유지.

## 순서와 리뷰

1 → 2 → 3 → 4 → 5 순서로 진행한다. 3·4·5가 모두 TopologyView를 만지므로 병렬로
돌리지 않는다. 리뷰는 1·4단계가 2인 정족수(R2), 3·5단계가 1인(R1), 2단계는
생략(R0)이다. 단계마다 브랜치·PR을 분리한다.
